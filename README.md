# BtAudioFixer
解决连接音响后无法播放声音的情况。
# BtAudioFixer.exe 使用教程

> 蓝牙音箱"连上了但不出声"修复工具 · 文字版说明

---

## 一、这个工具解决什么问题

当你的蓝牙音箱出现下面这些情况时，本工具适用：

- 电脑显示音箱"已连接"，但放音乐**没有声音**
- 声音图标正常、音量也正常，就是不响
- **电脑睡眠/休眠唤醒后**，音箱就哑了
- 蓝牙设置里显示连着，任务栏音量里却看不到音箱的播放设备
- 时好时坏：刚连上有声，过一会儿又没声

**不适用的场景**（本工具帮不上忙）：

- 蓝牙适配器硬件坏了、设备管理器里是黄色感叹号
- 音箱本身故障或没电
- 从没配对成功过、搜不到设备
- 音箱音量旋钮被拧到最小

## 二、它到底改了什么

工具会依次执行 **5 个步骤**，全部是"关闭省电"和"重启服务"，**不会删除任何设备、不会清除配对、不会重装驱动**。

| 步骤 | 操作 | 为什么要这么做 |
|---|---|---|
| 1/5 | 关闭蓝牙适配器的 **USB 选择性挂起** | Windows 为省电会挂起 USB 蓝牙设备，一挂起 A2DP 音频通道就断，表现就是"连上没声" |
| 2/5 | 关闭电源计划里 **无线适配器节能模式**（交流 + 电池） | 同上，防止系统主动降功耗掐断链路 |
| 3/5 | 关闭电源计划里 **USB 选择性挂起**（交流 + 电池） | 同上，覆盖 USB 总线的省电策略 |
| 4/5 | **重启蓝牙音频服务栈** | 让 `BTAGService`、`BthAvctpSvc`、`bthserv` 重新加载，重建音频链路 |
| 5/5 | **校验当前状态** | 读回设置确认改成功了，并报告音箱端点是否已挂载 |

> **关于"USB 选择性挂起"**：这是核心。蓝牙适配器在系统里通常有**两个**设备节点——一个父级 `USB Composite Device`，一个子级适配器本体。**只改子级是不够的**，父级仍会挂起并带走音频通道。本工具会把两个都改掉。

## 三、运行前的准备

### 1. 必须用管理员权限

工具**已内置管理员清单**，双击时会**自动弹出 UAC 提权窗口**。

弹出时点 **"是"** 即可。

- 如果点了"否"，工具会提示"需要管理员权限"并退出（退出码 2），此时设置什么都没改。
- 如果 UAC 窗口没弹出来，右键 exe → **"以管理员身份运行"**。

### 2. 确认要修的设备已连接

先把蓝牙音箱**开机并连上电脑**，再运行工具。工具只修改电源策略和服务，不会主动帮你连接音箱。

### 3. 建议先关掉正在播放的音乐

服务重启会让当前播放**中断几秒**。正在打游戏或开会的话，建议挑个空闲时间。

## 四、三种用法

### 用法 A：双击运行（最常用）

直接双击 `BtAudioFixer.exe` → UAC 点"是" → 等它跑完 → 按任意键退出。

跑完会看到类似这样的结果：

```
  ==============================================================
    蓝牙音箱 A2DP 掉线修复工具  BtAudioFixer
    针对: 蓝牙连接正常但音箱无声 / 睡眠唤醒后掉线
  ==============================================================

模式: 修复

  >> 1/5  关闭蓝牙适配器 USB 选择性挂起
      000000000
      7&1d754fa2&0&0000
  ...
  >> 5/5  校验当前状态
  [适配器选择性挂起]
      000000000  = 0  已关闭 OK
      7&1d754fa2&0&0000  = 0  已关闭 OK
  [A2DP 播放端点]
      HUAWEI AI Speaker2-01571 Stereo -> ACTIVE 已挂载 OK

==============================================================
  修复完成: 12 项成功, 0 项失败
  建议重启一次电脑, 使适配器电源策略完全生效。
==============================================================
```

**关键看最后两行**：`0 项失败` 就是全部成功。然后看 `A2DP 播放端点` 那行是不是 `ACTIVE 已挂载 OK`。

### 用法 B：只检查，不修改

想先看看当前状态有没有问题，用命令行加 `--check`：

```cmd
BtAudioFixer.exe --check
```

这个模式**不做任何修改**，只读状态并报告。适合：

- 想确认之前修的还在不在
- 出问题时先看一眼，判断是不是同一个毛病

输出示例：

```
模式: 仅检查 (不修改)

  [适配器选择性挂起]
      000000000  = 0  已关闭 OK
      7&1d754fa2&0&0000  = 0  已关闭 OK
  [A2DP 播放端点]
      HUAWEI AI Speaker2-01571 Hands-Free AG Audio -> state=268435464 (免提通道, 非播放端点)
      HUAWEI AI Speaker2-01571 Stereo -> ACTIVE 已挂载 OK
```

### 用法 C：安静模式（不等待按键）

跑完直接退出，不显示"按任意键退出"。适合批处理或脚本调用：

```cmd
BtAudioFixer.exe --quiet
```

### 参数一览

| 参数 | 作用 | 会修改系统吗 |
|---|---|---|
| （不加参数） | 完整修复 + 等待按键 | ✅ 会 |
| `--check` | 只检查并报告 | ❌ 不会 |
| `--quiet` | 完整修复，但不等待按键 | ✅ 会 |
| `--check --quiet` | 只检查且不等待 | ❌ 不会 |

## 五、结果怎么看

### 情况 1：显示 `0 项失败`，端点是 `ACTIVE`

修好了。可以直接去放首歌试试。

**建议重启一次电脑**——适配器的电源策略在重启后才完全生效，重启前可能还会偶尔抖一下。

### 情况 2：显示 `N 项失败`

看失败的是哪一步：

- **第 1 步失败**（写注册表失败）→ 多半是**没有真正拿到管理员权限**。右键 → 以管理员身份运行，重试。
- **第 2、3 步失败**（powercfg 退出码非 0）→ 同样是权限问题。另外如果你用的是公司电脑，可能有组策略锁定了电源设置，这时需要联系 IT。
- **第 4 步失败**（服务重启失败）→ 某个蓝牙服务被别的程序占用或已被禁用。手动到 `services.msc` 里把 `BTAGService`、`BthAvctpSvc`、`bthserv` 三个服务启动类型设为**手动**，然后重启电脑。

### 情况 3：显示全部成功，但端点是 `UNPLUGGED`

说明**电源策略不是这次的病因**，还有别的原因。工具本身无能为力，需要进一步排查。按顺序试：

1. 把音箱**关机再开机**，重新连一次（音箱侧状态机卡死很常见）
2. 确认**手机没连着这个音箱**——很多音箱只允许一个音源，手机占着电脑就放不出声
3. 在「设置 → 蓝牙和设备」里，把音箱**删除设备**后重新配对
4. 换一个 USB 口插蓝牙适配器（**优先主板后置 USB 口**，避开前置面板和 USB Hub）
5. 去音箱厂商官网看看有没有固件更新

## 六、常见问题

**Q：跑完了，当时有声，过一会儿又没声了？**

说明还有第二个原因（音效增强、编解码协商失败、适配器固件等）。重新跑一遍可以临时恢复，但根治需要抓到掉线瞬间现场。可用配套的 `bt-watch.ps1` 长时间监控来定位。

**Q：会不会把我配对的设备删掉？**

不会。工具**只改电源策略和重启服务**，不碰配对记录、不删设备、不动驱动。

**Q：改了电源设置，会不会更费电？**

会略微增加待机功耗。但注意：**关闭的是"选择性挂起"，不是禁止睡眠**。电脑该睡眠还睡眠，只是不再为省电而切断 USB 蓝牙设备。

**Q：我是笔记本，拔了电源会不会又被改回去？**

不会。工具对**交流（插电）和电池（不插电）两种模式都设成了关闭**，两边都覆盖了。

**Q：运行后要重启吗？**

**建议重启一次**，让适配器电源策略彻底生效。不急的话，不重启也能用，只是可能还会抖一两次。

**Q：为什么工具显示"父级设备"和"子设备"两个节点？**

因为蓝牙适配器在 Windows 里就是这样枚举的：一个 `USB Composite Device` 父节点 + 一个适配器子节点。**两个都要关掉选择性挂起**，只改一个会漏。

**Q：杀毒软件报警怎么办？**

这是自己编译的小工具，无数字签名，可能被误报。源码 `BtAudioFixer.cs` 就在同目录，可以自行审计或重新编译：

```cmd
csc /nologo /target:exe /platform:anycpu /optimize+ ^
    /win32manifest:BtAudioFixer.manifest ^
    /out:BtAudioFixer.exe BtAudioFixer.cs BtAudioFixer.AssemblyInfo.cs
```

（`csc.exe` 位于 `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\`）

## 七、安全与回滚

### 这个工具是安全的

- 不改配对记录、不删设备、不卸载驱动
- 所有修改都是**可逆的设置项**
- 每一步都打印结果，出错会明确告诉你是哪一步

### 想还原怎么办

工具改的东西都可以手动改回来：

| 改了什么 | 怎么还原 |
|---|---|
| USB 选择性挂起 | 设备管理器 → 找到蓝牙适配器 → 属性 → 电源管理 → 勾回"允许计算机关闭此设备以节约电源" |
| 电源计划节能 | 控制面板 → 电源选项 → 更改计划设置 → 更改高级电源设置 → 无线适配器设置 / USB 设置 → 改回"中等节能" |
| 服务重启 | 无需还原，重启服务是临时的 |

### 备份

每次修复前建议备份注册表。本目录下的 `bt-backup-<时间戳>\` 就是历史备份，双击里面的 `.reg` 文件即可导入还原。

## 八、配套工具

| 文件 | 用途 |
|---|---|
| `BtAudioFixer.exe` | 主修复工具 |
| `BtAudioFixer.cs` | 源码，可自行审计/编译 |
| `BtAudioFixer.manifest` | 管理员权限清单 |
| `BtAudioFixer.AssemblyInfo.cs` | 版本信息 |
| `bt-watch.ps1` | 长时间监控，抓掉线现场快照 |
| `bt-audio-monitor.ps1` | 短时状态采样 |
| `bt-backup-*\` | 注册表备份 |

### 监控脚本用法

```powershell
# 监控 8 小时，每 5 秒采样一次（默认）
powershell -ExecutionPolicy Bypass -File bt-watch.ps1

# 监控 2 小时，每 3 秒采样
powershell -ExecutionPolicy Bypass -File bt-watch.ps1 -Hours 2 -IntervalSec 3
```

运行后会在同目录生成：

- `btwatch-<时间戳>.log` —— 主日志，每行一条状态记录
- `btwatch-snapshots-<时间戳>\` —— **掉线瞬间的完整现场快照**，每次状态变化存一份

快照里包含：端点状态、链路计数、适配器挂起设置、服务状态、相关设备节点、近 5 分钟系统事件日志。**这是定位真正根因的关键证据。**

## 九、一句话总结

> 双击 → UAC 点"是" → 看到 `0 项失败` → 重启电脑 → 音箱有声了。

如果这样还不行，说明病因不在电源策略，运行 `bt-watch.ps1` 抓现场再排查。
